Root cause: bot/flow.js handleSterge() (line ~907-914) calls only
registry.updateSite(site.id, { status: 'deleted', url: null }) for every site
returned by registry.listSites(tgUser.id). It never calls
webpublish.unpublishSite(site), which is the function that actually removes
$DATA_DIR/published/<slug>/ from disk (see bot/webpublish.js line ~51-108).
bot/server.js's /live/<slug>/ route (serveLive, line ~721) serves straight from
that directory with no registry status check at request time, so a paid, live
site is unaffected by /sterge.
