# HANDOFF — templates/product-menu (Wave 5, round-3 audit remediation)

Owner: this wave touched only `templates/product-menu/{template.html,styles.css,script.js,schema.json,presets.json}`
and added `bot/test/wave5-product-menu-fixes.test.js`. Everything below is either done, or blocked on a file

## What's fixed (see bot/test/wave5-product-menu-fixes.test.js for the oracle, one check per item)

1. **CLS 0.18 desktop / 0.17 mobile → 0.00 / 0.00.** The real cause was not oversized images (those already
   had `aspect-ratio` boxes reserved in `styles.css`) — it was the cookie-consent banner. `cookie-banner.css`
   (generated by `bot/site-legal.js`, shared across all 5 templates) adds hero-clearance padding via
   `body:has(#hb-cookie-banner:not([hidden]))` / `html.hb-cookie-open`, but that stylesheet was linked near the
   end of `<body>`, after `cookie-banner.js` had already removed the banner's `hidden` attribute. The clearance
   padding therefore applied *after* first paint, once the stylesheet finally arrived, producing one large,
   measurable shift. Fixed inside `template.html` only: moved the `<link rel="stylesheet" href="cookie-banner.css">`
   into `<head>`, and added a small synchronous inline `<script>` (also in `<head>`) that checks
   `localStorage`/cookie consent and sets `documentElement.classList.add('hb-cookie-open')` *before* first
   render when consent hasn't been given yet — mirroring exactly what `cookie-banner.js` decides later, so the
   layout is correct from frame one instead of jumping.
   - Measured with Playwright + CDP network throttling (150ms RTT, 1.6Mbps down, 4x CPU) on the `casa-nord`
     preset. Before: 0.1810 (1440px) / 0.1663 (390px). After: 0.0000 / 0.0000. Screenshots and
     `cls-results.json` under `04-QA-Evidence/Wave5-product-menu/`.
   - **This same cookie-banner.css/js load-order problem likely affects the other 4 templates too** (they all
     paste the identical `<link>`/`<script>` pair near the end of `<body>`). Fixing it there means the same
     two edits in each template's `template.html` — cheap, but out of this wave's file ownership.
   - Web-font check: product-menu uses only system font stacks (`--font-display`/`--font-text`/`--font-ui`
     all resolve to platform serif/sans fallbacks, no `@font-face` or Google Fonts `<link>` anywhere in this
     template) — so there was no font-swap CLS risk to fix here.

2. **Gallery lightbox now fully styled.** `collage.js` (also owned by this wave) creates `.lightbox`,
   `.lightbox-img`, `.lightbox-close`, `.lightbox-nav` elements on click, but `styles.css` had zero rules for
   any of them — clicking a photo dumped an unstyled, in-flow `<div>` into the page instead of opening a
   viewer. Added the full `.lightbox*` rule set (fixed full-screen overlay, dark backdrop, centered image,
   close/prev/next controls sized for touch, reduced-motion override).

3. **Hero CTA no longer transparent.** The primary "Rezervă o masă" button carried both `.hero-cta` (shared
   with the ghost/secondary button) and `.pm-hero__cta--fill`. `.hero-cta`'s `background: transparent` was
   declared *after* `.pm-hero__cta--fill`'s `background: var(--cta)` in the stylesheet, so at equal
   specificity it always won the cascade. Removed the redundant `hero-cta` class from the primary CTA's
   markup in `template.html`.

4. **Mobile navigation added.** The header nav was `display:none` below 834px with no fallback. Added a
   44×44 hamburger button (`#pm-mast-burger`) that toggles `#pm-mast-nav` as an accessible dropdown:
   `aria-expanded`/`aria-controls`, closes on Escape / outside click / link activation / resize past the
   desktop breakpoint, `prefers-reduced-motion` respected.

5. **Instagram URL fields — kept separate, wired to stay in sync (see "Decision" below).**

6. **WCAG AA contrast fixed.** Sampled real rendered pixels (screenshot → canvas, not raw `getComputedStyle`
   rgba values, since several of the affected colors are translucent) to compute true contrast ratios:
   - `--ink-mute` (used for `.pm-rail__label`, `.pm-meta`, `.menu-lang-btn`, `.pm-social__handle`, `.pm-foot`)
     was `rgba(26,20,16,0.5)` on the cream body → 3.34:1. Raised to `0.62` alpha → 4.85:1.
   - `.pm-scroll`/`.scroll-indicator` text was `rgba(255,255,255,0.42)` on the void hero → 4.05:1. Raised to
     `0.52` alpha → 5.69:1.
   - Everything else sampled (mast nav, kicker, hero tag, CTAs, gallery captions, contact links, attribution
     line) was already ≥ 4.5:1 (or ≥ 3:1 for large text) and left untouched.

7. **Footer Instagram/Facebook icon tap targets fixed.** They were plain text links ("IG"/"FB") with no
   padding — ~13×19px and ~16×19px. Now 44×44 circular tap targets (`.pm-foot__soc a`), with a negative
   margin on the container so the visual footer spacing is unchanged.

8. **200% zoom reflow fixed.** At an emulated 200% zoom on the mobile viewport (390px → 195px CSS width),
   the mast bar (brand wordmark + the new hamburger + the persistent "Rezervă o masă" pill) no longer fit and
   forced horizontal scroll. Fixed with a `max-width: 360px` breakpoint that tightens the bar's padding/gap,
   truncates the wordmark with an ellipsis (`min-width:0` + `overflow:hidden` on the flex item), and lets the
   CTA pill wrap onto two lines instead of overflowing (kept it flex-shrinkable; only the hamburger keeps
   `flex-shrink:0` since its 44×44 tap target must never shrink). Verified no overflow at 720px (desktop
   200%) and 195px (mobile 200%); the original 1440/390 layouts are pixel-identical to before at that
   breakpoint's threshold.

## Decision: Instagram URL fields — kept in sync, not merged

The audit (medium #1) flagged `instagram.url` (drives the feed follow-button + IG photo grid, gated behind
`instagram.handle`/`embedUrl` "is a partner feed actually connected" logic in `build.js`'s
`normalizeInstagramForPublic`) and `contact.instagram.url` (drives the contact-card chip + footer icon) as
duplicate, editable independently, and prone to drifting apart.

**I first merged them into one field** (`contact.instagram.url` only, `instagram.url` removed from the
schema and template). That is the *cleaner* fix and I'd recommend it long-term. It broke a pre-existing,
unrelated oracle: `bot/test/s107-s106-advocate.test.js` hardcodes both fields' existence and their *exact*
schema labels (`assert.strictEqual(schemaFieldLabel(schema, 'instagram.url'), 'URL Instagram (https://www.instagram.com/...)')`,
same for `contact.instagram.url` → `'Instagram (secțiune contact)'`). That test file is not owned by this
wave (not a new `wave5-product-menu-*` file), so I reverted the merge.

**What's actually shipped:** both fields still exist, with their original exact labels (satisfying
`s107-s106-advocate`), but each now carries a `hint` telling the editor to mirror the other field's value —
the two shipped presets (`casa-nord`, `traista-verde`) already keep them identical, and
`wave5-product-menu-fixes.test.js` asserts they stay that way. This doesn't eliminate the drift risk the
audit flagged, it only reduces it (an editor who reads the hint will keep them in sync; one who doesn't,
won't) — see below for the real fix.

**To actually finish this**, pick one:
- Update `bot/test/s107-s106-advocate.test.js` to expect the merged shape, then re-apply the merge (remove
  `instagram.url`, point the feed follow-button + IG grid at `contact.instagram.url` in `template.html`).
  This is the fix I'd ship if that test were in scope.
- Or, in `builder/app.js` (drawer save handler) or `build.js` (`normalizeConfigForRender`), auto-mirror one
  field into the other whenever they differ, so both stay correct regardless of which one an owner edits.

Either requires touching a file outside `templates/product-menu/**`, hence this handoff instead of a direct
edit.
